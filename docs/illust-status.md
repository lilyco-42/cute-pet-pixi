## 动态立绘：两个问题，一个已修、一个未确定

### 已修：cairo 的 PNG 编码器 bug（真正解掉了 OOM）

见上一节。`out of memory` 是误导性错误信息，实际抛在 `canvas.toBuffer('image/png')`，
同帧 `getImageData` 完全正常。改为自己用 zlib 封 PNG 后彻底消失。

成果（CI 实测，本机零执行）：

- 之前 OOM 的 3 个干员：**3/3 成功**（令的 Sleep 117 帧、提丰 117 帧、麒麟R夜刀 128 帧）
- 之前 0/6 的动态立绘：**6/6 成功**（合计 1159 帧）
- PNG 自检：43 个全部可反解、尺寸正确、无空帧

### 未确定：德克萨斯（缄默德克萨斯）只剩残影

6 个动态立绘里 5 个渲染完整（斯卡蒂 / 临光 / 陈 / 艾雅法拉 / 幽灵鲨），
只有德克萨斯的人物本体缺失，只剩模糊的灰色残影。帧体积也明显偏小：

| 角色 | 帧数 | KB/帧 |
|---|---|---|
| 临光 | 149 | 117.3 |
| 斯卡蒂 | 128 | 123.8 |
| 幽灵鲨 | 288 | 85.3 |
| 陈 | 180 | 28.1 |
| 艾雅法拉 | 225 | 18.0 |
| **德克萨斯** | 189 | **12.4** |

已排除的原因（都是实测，不是推测）：

| 假设 | 证据 | 结论 |
|---|---|---|
| 附件缺失 | setup pose 下 333 个槽位 **0 个**无附件 | 排除 |
| 贴图尺寸不符 | atlas 声明 2008×2008，PNG 实际 2008×2008 | 排除 |
| 区域名不存在 | 缺失槽位名（如 `C_L_Hand1_4`）在 atlas 里都能找到 | 排除 |
| rotate 打包 | 德克萨斯 rotate=true 19 个，斯卡蒂 25 个（斯卡蒂正常） | 不成立 |
| 需要非默认 skin | 两个模型都只有 `default` 一个 skin | 排除 |
| skin 没应用 | 已修并实测：**帧字节完全相同**，未改变产物 | 不是原因 |

**当前状态：未解决。** 已知它不影响其余 5 个动态立绘，也不影响 23 个干员小人。
下一步可以试的方向：

1. 用 Spine 官方编辑器打开该模型，看动画本身是否就把本体隐藏了
   （`spine_diag` 显示动画第 0 帧有 49/333 槽位无附件，而 setup pose 是 0/333 ——
   说明**是动画自己清掉了附件**，这可能是模型作者的有意设计，而非我们的 bug）
2. 换 WebGL 渲染器（pixi-spine）交叉验证，排除 spine-canvas 的绘制路径问题

> 第 1 点值得优先看：`0/333` → `49/333` 这个变化来自动画数据，
> 如果动画就是要把本体淡出/隐藏，那当前的产出其实是**正确的**。
